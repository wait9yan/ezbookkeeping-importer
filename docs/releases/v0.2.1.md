# v0.2.1 发布说明

状态：已发布。正式发布工作流已通过，见 [GitHub Release](https://github.com/wait9yan/ezbookkeeping-importer/releases/tag/v0.2.1)。本版本只包含数据目录权限修复，启动自动数据库迁移属于后续源码改动。

修复 Docker 挂载数据目录属于 `root:root`、权限为 `755` 时，无法生成 `config.toml` 而反复退出的问题。镜像采用 PostgreSQL 官方镜像的启动模式：先以 root 准备必要的数据权限，再通过 `gosu` 切换为 `10001:10001` 执行业务命令。

## 行为变化

- 默认部署无需手动 `chown`。缺失的 `config.toml` 仍由共用 CLI 使用内置默认值生成；已有配置和数据内容保留。
- 权限准备仅处理 `/app/data`、默认配置，以及后台运行需要的 `email`、`reports`、`logs`。按需调整宿主机对象的所有权和 owner 权限，不沿符号链接修改其他位置。
- 显式设置非 root `user: "UID:GID"` 时保留指定身份，并跳过权限准备；部署者负责提供相应访问权限。
- `docker compose exec … ebki` 同样经过降权入口。帮助命令不修改数据；只读维护命令由降权后的 CLI 判断配置是否可读。
- 只读存储、NAS ACL 等禁止必要写入或权限修复时仍明确报错。

## 升级

升级至本版本时，先停止 importer，再拉取并重建服务：

```sh
docker compose stop importer
docker compose pull importer
docker compose up -d --force-recreate importer
docker compose logs --tail 100 importer
```

如需固定版本，在部署环境中设置 `EBKI_IMAGE=ghcr.io/wait9yan/ezbookkeeping-importer:0.2.1`；自定义 Compose 未使用该变量时，直接修改 importer 的 `image`。已有 `.env`、`data/config.toml` 和挂载路径保留。本版本未修改数据库结构，无新增迁移要求；首次部署仍须执行 `migrate`。

启动会恢复正常邮件导入与账本写入。权限修复不替代服务连接配置；内网 ezBookkeeping 未启用 TLS 时应使用 `http://ezbookkeeping:8080`。
