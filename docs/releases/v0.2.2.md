# v0.2.2 发布说明

状态：已发布。正式发布工作流已完成，见 [GitHub Release](https://github.com/wait9yan/ezbookkeeping-importer/releases/tag/v0.2.2)。

## 行为变化

- `run` 与 `migrate` 共用数据库准备流程：明确缺库时创建指定目标库，空库初始化，受支持旧库依次执行未应用迁移；校验完成后才开始业务工作。
- `doctor` 只读检查迁移历史和结构就绪，不执行迁移；仍不连接 IMAP、不调用模型、不测试实际入账。
- 每版迁移独立事务提交。失败只回滚当前版，前序已提交版本保留，再次启动继续；结构漂移、损坏、历史断链、脚本改写或数据库版本超前均明确拒绝，不自动修复或降级。
- README 精简为使用入口，移除包版本描述；详细运维及开发者迁移说明集中到 docs。

数据库已是目标结构时，校验无需 DDL 权限。缺库创建需要维护库 CONNECT 与 CREATEDB，初始化需要 schema 建表权限；升级既有对象需要相应对象所有者或迁移权限。旧 v1 的迁移历史元数据也需一次升级，普通账号权限不足时，由管理员先执行 `migrate`，再以普通账号运行。

详细边界见[数据库初始化与版本迁移](../operations.md#数据库初始化与版本迁移)，新增 SQL 的开发流程见[数据库结构变更与发布](../database-migrations.md)。

## 升级与回退

升级前停止旧 worker 和旧版本维护写入，配对备份 **importer 数据库、邮件原件与配置**。保留现有服务连接及挂载路径，不支持混合版本滚动运行。

**以下示例仅在正式镜像可用后执行。** 在部署目录的 `.env` 设置 `EBKI_IMAGE=ghcr.io/wait9yan/ezbookkeeping-importer:0.2.2`，然后按顺序操作：

```sh
docker compose stop importer
# 确认没有并发维护写入，再完成数据库、原件与配置的配对备份。
docker compose pull importer
docker compose run --rm importer migrate
docker compose run --rm importer doctor
docker compose up -d --no-build
docker compose exec -T importer ebki status
docker compose logs --tail 100 importer
```

启动后会恢复实际账本写入。镜像回退必须同时兼容当前数据库结构和迁移历史，不恢复数据库，也不撤销已写入账本的交易；恢复较早备份须先核实远端状态。完整步骤见[镜像升级与回退](../operations.md#镜像升级与回退)及[备份与恢复](../operations.md#持久化备份与恢复)。
