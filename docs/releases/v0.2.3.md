# v0.2.3 发布说明

修复 `0.2.2` 在 `postgres:18-alpine` 上初始化新库时误报 `schema_drift` 的问题：首版 SQL 已执行，但约束查询的排序差异导致结构复检失败，事务回滚后重启仍重复失败。

## 修复与边界

- 生成器和运行时共用的提取器在 namespace 规范化后使用 Python 确定性排序，消除数据库排序规则差异；保留全部字段、重复数量和表内列顺序。
- 通过真实 PostgreSQL 重新生成结构契约。迁移 SQL、脚本校验和及数据库结构版本 v2 不变，无须增加 `003` 迁移或删除数据库。
- 已有空库可继续初始化；旧 v1 升级仍需要原有迁移权限。真实结构损坏、内容差异及历史异常依然明确拒绝，不自动修复或降级。

## 升级

启动会恢复实际账本写入。**如果已删除 importer 数据库，而远端账本仍有历史交易，必须先恢复配套备份或完成历史核对，再启动 run。** 本修复不会恢复已删除的导入状态，也不能替代远端历史核对。

在部署目录的 `.env` 设置 `EBKI_IMAGE=ghcr.io/wait9yan/ezbookkeeping-importer:0.2.3`，停止旧 worker 和旧版本维护写入，配对备份数据库、邮件原件与配置后执行：

```sh
docker compose stop importer
# 确认没有并发维护写入，完成配对备份。
docker compose pull importer
docker compose run --rm importer migrate
docker compose run --rm importer doctor
docker compose up -d --no-build
docker compose exec -T importer ebki status
docker compose logs --tail 100 importer
```

迁移权限见[数据库初始化与版本迁移](https://github.com/wait9yan/ezbookkeeping-importer/blob/v0.2.3/docs/operations.md#数据库初始化与版本迁移)，数据恢复见[备份与恢复](https://github.com/wait9yan/ezbookkeeping-importer/blob/v0.2.3/docs/operations.md#持久化备份与恢复)。镜像回退须同时兼容当前结构和迁移历史，不撤销已写入账本的交易；详见[升级与回退](https://github.com/wait9yan/ezbookkeeping-importer/blob/v0.2.3/docs/operations.md#镜像升级与回退)。

## 验证

修复提交的本地隔离验收已通过：575 项单元测试；PostgreSQL 17/18 × Bookworm/Alpine 各 209 项非生产集成及契约再生成；AMD64/ARM64 各 Bookworm/Alpine 实际镜像验收。覆盖首版复检失败后完整回滚与重试、旧库升级、真实内容差异拒绝，以及首次写入和中断恢复后不重复入账。正式发行镜像由版本标签工作流执行质量检查及上述环境矩阵验收后发布。
