# v0.3.3 发布说明

修复日报与月账单因商户描述不同而重复记账的问题。关联使用银行原交易金额；美元日报关联月账单后，使用银行人民币结算额更新同一笔交易。

v0.3.2 标签的镜像验收未通过，正式镜像和 GitHub Release 均未发布。本版本保留该失败标签，包含同一去重修复，并修正镜像验收的合成交易事实，继续验证发送前检查及真实强杀恢复。

## 修复与行为变化

- 日报与月账单按交易日、卡号、消费或退款类型、银行原交易金额寻找来源候选。结构一对一且双方唯一时自动关联，商户描述不同、月账单未标原币币种不再单独阻止正常关联；原始商户文本和银行事实保留。多候选时描述只作辅助证据，不能按列表顺序任意合并，同值真实多笔继续保留数量。
- 日报先记录美元消费、月账单后给出人民币结算额时，沿用已有 `settle_currency` 流程，在同一远端交易 ID 上修改账户和金额。原币事实、准确时间、用户分类、备注、标签和图片保留；不另建一笔人民币支出，不根据自行取得的汇率推算结算金额。
- 月账单先到且查重确认没有已有消费时，按银行人民币结算额补录一次。后到日报关联已有身份并补充来源证据，不再新增美元支出，也不把已确认的人民币决定改回美元。
- 账本重复候选同时覆盖同卡美元账户的原交易金额、人民币账户的银行结算金额，隐藏历史账户仍参与查重。不同备注不能单独排除候选；旧版已冻结的人民币暂估金额也保留为查重依据。
- 所有新增交易都在发送前再次检查重复候选，日报和月账单使用相同的结构筛选政策。人工“确认新建”仍只豁免已确认且未变化的候选；新增或变化的候选继续阻止发送。
- 已知来源标记独立核实；写入结果不明仍先核实原操作，不盲目重发。明确币种冲突、卡号歧义、远端账户或金额被修改、查询失败等情况暂停处理，不生成替代支出。
- 镜像验收补齐合成待写交易的卡号和准确时间，确保发送前检查能到达真实写入登记及强杀暂停点；保留原有超时、写入核实和恢复断言，不放宽业务校验。

例如：日报先记录 USD 10.00，月账单提供原交易金额 10.00 与银行结算 CNY 72.00。系统关联两份来源，再把已有交易更新为人民币 72.00；查重无需把 10.00 与 72.00 直接比较，也不需要推算银行汇率。

## 升级

本版本没有新增数据库迁移，结构版本仍为 **4**，没有新增业务配置项。

从已完成迁移的 v0.3.0 或 v0.3.1 升级，先停止 worker 和并发维护写入，配对备份 importer 数据库、邮件原件与配置。在 `.env` 中固定 `EBKI_IMAGE=ghcr.io/wait9yan/ezbookkeeping-importer:0.3.3`，然后执行：

```sh
docker compose stop importer
docker compose pull importer
docker compose run --rm importer doctor
docker compose up -d --no-build
docker compose exec -T importer ebki status
docker compose exec -T importer ebki issues --format text
```

上述命令仅为后续部署说明，本次本地发布准备没有执行生产部署。

已有来源未关联或重复诊断需要先查看当前问题，再按快照执行定点 `recheck`、关联或确认。升级不会把已入账的两笔历史交易自动合并，**包括已识别的 RESEND、DMIT 历史重复**；也不会删除远端交易。历史合并需要另行核实来源、账户、用户修改及写入状态后单独处理。

纯远端、没有本地来源的手工美元记录可以成为重复候选并阻止新增，但不会被本版本自动关联或修改；现有外部手工关联仍限人民币目标。不能把发现候选等同于已完成结算。

**从 v0.2.x 直接升级，仍须先遵循 [v0.3.0 升级说明](https://github.com/wait9yan/ezbookkeeping-importer/blob/v0.3.3/docs/releases/v0.3.0.md) 中的旧还款清理和配置调整。** 正常启动虽具备自动迁移能力，含旧还款数据的 003 迁移仍要求一次性清理工具；执行旧说明时应将镜像固定为目标 `0.3.3`。

## 验证范围

本地最新 **636 项单元测试通过**，包括两项新增镜像夹具回归；去重修复的 **270 项完整隔离 PostgreSQL 集成测试通过**，3 项真实账本测试因未配置隔离账本上下文跳过。Ruff、mypy（63 个源文件）、wheel/sdist 构建通过，覆盖不同商户描述、美元到人民币的同 ID 完整结算、月报先到后日报、原币与结算候选、旧人民币暂估、同值多笔、发送前复查、UNKNOWN 和用户字段保护。

已使用包含本次修复的同一个本机 ARM64 镜像，通过原始验收脚本连接 PostgreSQL 17 Bookworm、18 Alpine 的完整检查：全新默认启动、旧库升级、权限与单进程锁、写前强杀后保留 UNKNOWN 且零新增、远端接受后强杀再启动核实且不重发。未延长等待或放宽恢复断言；这项本地镜像验证不代表正式双架构发行已完成。

PostgreSQL 17/18 × Bookworm/Alpine、AMD64/ARM64 镜像与正式镜像发布结果，以本次版本标签工作流为准。本地通过不表示多架构镜像验收或生产部署已完成。
