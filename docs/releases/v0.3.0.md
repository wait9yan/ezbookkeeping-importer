# v0.3.0 发布说明

本版本增加历史月账单消费和退款的自动补录，并移除自动还款功能。**升级涉及数据库迁移和旧还款数据清理；新版启动后会实际补录历史账单，不存在 dry-run 或逐批审批。**

## 功能与修复

- 缺少日报时，按月账单人民币结算金额自动记入对应卡片的人民币账户；消费为正支出、退款为负支出。原币未知保持未知，不根据交易地猜币种。月账单还款不补录。
- 缺来源与缺入账分别核查。已有手工账候选、来源歧义、账户缺失和查询失败形成问题，不当作零候选创建。隐藏同卡账户参与查重，已知来源标记不会因账本金额或账户变化而被忽略。
- 新增稳定来源关联：月报补录后收到日报时复用交易身份；同值多笔保留数量；写入结果不明只核实，不盲目重发。
- 来源问题支持查看候选、关联内部或远端交易、重试和忽略；忽略仅作用于选中的来源行。详情见[维护命令](https://github.com/wait9yan/ezbookkeeping-importer/blob/v0.3.0/docs/operations.md#日志与单次维护命令)。
- 日报“预授权完成”按正金额消费解析，修复因此整封日报被阻塞的问题。历史被阻塞邮件需通过已有邮件问题的 `retry` 重新解析，不会仅因升级自动恢复。

## 不兼容变化

- 自动还款通知不再采集或入账，移除 `repayments` 和 `repayment_ownership_confirmed` 配置。保留这些旧字段会明确报配置错误。
- 迁移链新增 `003_remove_repayment.sql` 和 `004_transaction_sources.sql`，目标结构版本为 **4**。003 清除 importer 内的旧还款状态，004 回填来源关联并保留现有消费/退款的 ID、来源标记和远端关联。
- 一次性清理工具删除旧还款通知、原件、本地报告/交易/任务（包括未决写入）及相关可定位日志。**不会删除或修改 ezBookkeeping 中已有转账**；这些转账及未决还款结果需在升级前核实。
- `date_only_time` 独立用于月账单的日期型入账，应明确设置，例如 `date_only_time = "12:00:00"`；该值是记账约定，不是银行提供的交易时刻。已有配置不会自动补写，缺失时补录会报告问题。

## 从 v0.2.x 升级

1. 停止旧 importer 和所有并发维护写入；核实未决还款结果，并配对备份 importer 数据库、邮件原件与配置。不要删库重建：远端已有消费需要原有关联防止重复。
2. 在部署目录 `.env` 中固定 `EBKI_IMAGE=ghcr.io/wait9yan/ezbookkeeping-importer:0.3.0`。从 `data/config.toml` 删除 `[[repayments]]` 各节及顶层 `repayment_ownership_confirmed`；明确设置顶层 `date_only_time`，保持 `mail.source_id` 不变。
3. 正式镜像发布后执行：

   ```sh
   docker compose stop importer
   docker compose pull importer
   docker compose run --rm --entrypoint /app/.venv/bin/python importer /opt/ebki/maintenance/purge-repayment-history.py --data-dir /app/data
   docker compose run --rm importer doctor
   docker compose run --rm importer status
   docker compose run --rm importer issues --format text
   ```

   一次性工具使用 importer 数据库及原数据目录，持有 worker 排他锁，完成数据库迁移后清理文件。无旧还款记录也可执行；有旧记录而绕过工具直接迁移会明确拒绝。若任一步失败，保持 worker 停止，修复后按相同数据库与目录重跑；不要跳过失败直接启动。
4. 检查账户及分类配置：每张卡应唯一匹配可记账的 CNY 账户，并存在可用二级支出分类“其他杂项 → 待分类”。`doctor` 不连接邮箱、不测试模型或实际写入，不能代替业务验收。
5. 启动后将自动处理历史月报缺口，再检查完成状态与问题：

   ```sh
   docker compose up -d --no-build
   docker compose exec -T importer ebki status
   docker compose exec -T importer ebki issues --format text
   docker compose logs --tail 100 importer
   ```

清理工具不会删除外部备份、用户导出快照或 Docker 自身日志。非默认报告/日志目录的参数、执行失败恢复见[还款历史清理](https://github.com/wait9yan/ezbookkeeping-importer/blob/v0.3.0/docs/operations.md#移除自动还款功能的升级步骤)。

## 恢复与边界

- 新结构不能直接换回 v0.2.x 镜像。清理不可逆；恢复必须使用配套备份，且不能假定远端账本也回到了备份时刻。
- 若 v0.3.0 已补录，旧数据库备份可能缺少新写入的关联。恢复前须核实远端来源标记和实际记录，优先向前修复，避免再次补录。
- 查重无候选仅代表在记录的账户和时间范围未找到。移到其他日期/账户的手工账、其他渠道的并发写入仍可能需要人工核对；远端已删除的关联交易不会自动复活。

## 验证范围

功能提交已完成本地隔离验证：611 项单元、245 项 PostgreSQL 18 集成、41 项 PostgreSQL 17 交叉测试通过；3 项真实上游账本测试因未配置隔离账本上下文跳过。PG17 Bookworm 与 PG18 Alpine 的迁移契约一致，同一本地镜像通过首次启动、旧库升级、锁、强杀及重启恢复。两个独立容器的月报补录重跑保持一笔交易、一个目标、一次创建；该场景使用合成月报及持久化模拟账本，不代表生产账本验收。

正式发行镜像及 AMD64/ARM64 验收结果以版本标签工作流为准；本地验证不表示 GitHub Release、GHCR 镜像或生产部署已完成。
