# 错误与恢复

错误类型定义于 `domain/errors.py`。`ImporterError` 表达可安全展示的业务原因；`Conflict` 表达过期决定或状态冲突；`LedgerRejected` 表达确定业务拒绝；`LedgerError` 表达无法确认外部结果的故障。

## 错误矩阵

| 触发 | 结果 |
| --- | --- |
| 模板未知、字段不足、符号矛盾 | 保存原件及逐行问题，不静默丢行或猜事实。 |
| 模型异常、无效 JSON、候选 ID 非法 | 分类失败，不冒充有效 unmatched。 |
| 有效 unmatched | 使用精确绑定的临时分类；不是人工确认队列。 |
| 账户/分类无效 | 保存明确业务问题，发送前拒绝。 |
| POST 超时、响应丢失、进程中断 | UNKNOWN，禁止直接重发或另建交易。 |
| 回读查不到、多候选、查询失败 | 保持待核实，不能当成确定未写入。 |
| 结算目标缺失或类型改变 | 明确结算问题，不创建替代账单。 |
| 日志文件写失败 | stderr 明确诊断并抛错，不宣称持久化成功。 |

仅在批次隔离边界捕获一般异常，并保留有定位信息的持久问题；不得通过宽泛 try/except 返回成功值。CLI 业务错误应给出安全原因和非零退出码，配置错误应保留字段位置但去掉输入秘密。网络异常不直接打印 URL、Token 或 DSN。

实例：结果不明的创建操作即使一次查询返回空列表，也不能变回 queued。正确路径为保留 UNKNOWN 并继续核实原 `ebki-<UUID>`；人工命令只能记录后续意图，不能伪造未提交结论。

AI 分类决定同时保存适配器提供的 `audit`：模型名、提示词版本、最小候选分类快照及摘要、可得的标准 token 使用量。缺少 usage 表达为 null；不假设费用或将完整响应入库。候选名称变化必须反映为不同快照摘要；非整数或负 token 计数作为明确协议错误处理。


## PostgreSQL 连接与迁移诊断

`PostgresStore` 将已知连接 OperationalError、明确缺库及权限错误转换为安全 `DatabaseDiagnosticError`，保留阶段、分类码及可得 SQLSTATE。优先使用 SQLSTATE；libpq 启动故障未提供错误码时，仅识别已知格式并输出固定原因/排查步骤，不转发驱动原文。多种原因不能随意选一种；未知原因明确报告无法确定。非连接类 SQL 错误不得伪装为认证失败。

`migrate` 仅在明确缺库时尝试初始化连接串显式指定的库，经同一配置的 postgres 维护库创建后回连；不切换业务目标、不建角色。权限不足明确报错；其他命令不建库，认证/网络错误不触发创建。连接默认 10 秒超时，DSN 显式正整数 connect_timeout 受尊重；无限/无效值明确失败。

禁止为了避免秘密泄漏而只输出“OperationalError，检查配置”：诊断字段应来自安全分类，不能来自原始 DSN、密码或服务端任意消息。回归需包含不存在数据库、错误认证、网络拒绝/超时、未知文本及秘密不回显。
