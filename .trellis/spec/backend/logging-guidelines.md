# 日志事件与交互控制台

## 1. 范围与触发

适用于worker运行事件、JSONL轮转、Rich终端展示，以及统一run内控制台的日志尾随与命令输入。业务状态仍由数据库维护，日志不参与查重、任务领取、授权或恢复许可。

## 2. 接口与边界

- `application/events.py` 统一英文事件、字段、中文标题、进度与重复阻塞降噪；业务用例不导入Rich或创建日志文件。
- `adapters/logging.py` 配置标准logging；唯一worker持有`worker.jsonl`文件handler及轮转。取得worker锁后才创建写入handler。
- `ebki run`管理交互控制台与自有worker子进程。只有子worker执行业务流水线、取得worker锁并写JSONL；父控制台尾随日志、复用CLI解析与维护用例，不保留独立console入口。
- 控制台支持`help/status/issues/sync/recheck/exit`。每个业务命令在后台执行线程构造并关闭自己的Runtime/Store；不跨线程共享连接，不用shell/eval执行用户输入。
- run启动worker前固定尾随起点，已有日志从当时末尾读取，原先缺失的文件创建后从头读；托管worker不直接重复输出终端事件。就绪/失败/停止使用独立生命周期通道，不根据日志判断运行状态。

## 3. 输出与事件契约

文件始终JSONL。独立非TTY worker标准输出保持JSON；TTY可用Rich中文展示。统一run由控制台使用同一安全投影和中文标题渲染，通过prompt_toolkit代理输出，不能让日志覆盖输入行。

基础字段为`time/level/event/run_id/stage`；按事件使用`task_id/task_type/transaction_id/decision_version/attempt_id/email_id/source_item_id/report_key/counts/duration_ms/error_code/error_type/next_action`。字段必须进入统一白名单并校验类型，不能传任意请求、响应或业务字典。历史键只在统一投影中做有限兼容，不复制两套事件映射。

- 进度INFO最多每5秒一条且仅在处理数变化时输出；阶段开始、结束和错误立即输出。正常空轮询安静，非银行逐封筛除不写INFO。
- 有效模型unmatched是正常结果；重复候选、来源接纳等待处理状态用WARNING汇总，细节可DEBUG或通过issues查询。
- `sync_completed`只表示邮件采集完成；排队、尝试登记、API响应、回读确认必须用不同事件表达。
- `existing_link_restored`及`settlement_already_applied`可零发送完成，不能计为新写入。
- 核对发布提交和文件导出分开：导出失败事件注明结果已提交，不误报数据库回滚。
- 成功事件在事务提交及条件更新实际生效后发出；计数来自实际提交结果，不用UID上界、SQL尝试次数或候选意图数量猜测。
- 日志只携带必要对象标识和汇总。不得写入凭据、连接串、邮件正文/完整头、商户原文、金额、完整API请求响应、模型原始回答或人工理由。异常用安全代码/类型/阶段，堆栈不附局部变量或任意异常文本。

`data/config.toml` 顶层 `log_level` 控制日志级别，默认 INFO，修改后重启生效。容量固定 10 MiB、备份 5 个，不提供环境变量或 TOML 覆盖；Docker日志仍独立限额。文件日志与业务提交不是原子事务，不保证每次提交都一定有事件。

## 4. 验证与错误矩阵

| 情况 | 行为 |
| --- | --- |
| 日志目录非法、文件写入或轮转失败 | 明确抛出日志持久化故障并输出安全诊断，不转写临时文件 |
| 提交后的日志输出失败 | 不进入业务失败恢复分支，不倒改已经提交的交易/来源/核对状态 |
| API返回但回读未确认 | 输出结果待核实，不输出账本成功或重新发送 |
| 相同待处理原因反复轮询 | DEBUG或每5分钟汇总；按对象最近原因比较，首次/原因变化时WARNING，A→B→A也重新提示；降噪不影响真实业务重试 |
| console读取半行 | 等完整行后解析，不误报JSON损坏 |
| 日志重命名轮转或截断 | 正确继续读取；console不参与文件写入或轮转 |
| 畸形日志行 | 安全且可见的诊断，后续合法行仍可展示 |
| 日志文件缺失 | 明确提示等待创建，保留轮转期间暂时缺失语义 |
| 其他日志读取故障 | 安全诊断并结束统一入口，清理自有worker，不无限重试掩盖权限或I/O错误 |
| 无TTY调用run | 创建worker前明确失败，使用worker或单次CLI，不挂起等输入 |
| 命令执行期间再次输入业务命令 | 明确说明当前忙；help/exit/Ctrl+C与日志继续响应，不另建业务队列 |
| 后台命令结果展示出现意外异常 | 立即显式结束控制台，不等下一次输入才暴露；普通命令失败显示安全诊断后继续交互 |
| exit、Ctrl+C或EOF | 一起停止控制台和自有worker，等待已接受维护命令与当前处理阶段完成；不再进入后续阶段 |
| worker早退、初始化失败或已有worker冲突 | 明确失败，不继续显示正常提示符、不自动附着或重启；日志级别不影响判断 |
| 退出时仍在处理 | 显示等待收尾并继续输出日志，不以短固定计时器强杀，不因重复中断重复清理 |

## 5. 正常、基础与错误情形

正常：连续采集五千封邮件时每5秒显示一次已处理/采集/筛除/失败计数，终端仍能编辑中文命令。基础：无任务的轮询不每30秒打印一组开始结束。错误：API超时后显示“写入失败可重试”，或仅发现原marker便显示“已入账”。

## 6. 必需测试

保留文件追加/轮转/脱敏/磁盘故障回归；新增进度限频、事件字段不会丢失、成功提交/回滚/未命中边界、分类unmatched/重复候选汇总、UNKNOWN及零attempt恢复、核对发布后导出失败。控制台验证中文输入与日志交错、补全/历史、命令反馈、非TTY、轮转/截断/半行；统一run验证启动日志不丢不重、ERROR级别就绪、子进程异常可见、exit/Ctrl+C/EOF一起退出及数据库锁释放，旧console/quit命令移除。后端测试每命令整体60秒硬超时，真实账本写入不用于这些测试。

## 7. 错误与正确做法

错误：业务模块各自初始化handler；console与worker同时轮转同一文件；捕获日志故障后把已booked交易改为issue；打印provider原始响应查错；创建持久日志去重/审计表。

正确：入口集中配置、用例发出统一事件、文件唯一写入者、显示与业务执行分离；通过数据库事实处理命令，日志仅提供诊断与进度。

## 8. 命令结果展示

交互控制台的命令结果使用中文摘要、Rich表格和下一步提示，不能追加原始JSON/Python字典。单次CLI继续返回结构化JSON；两者消费同一份应用结果，纯展示层不得查库、改变状态或复制任务资格判断。

status区分采集、解析、交易、任务与当前诊断，不能把问题行数标成失败交易数；控制台issues进入按原因分组的交互处理，已有实体/对象筛选限定导航范围；单次CLI issues继续只读JSON。上下文保留可定位ID和必要业务信息，长ID不可只留下无法查找的截断值；缺失数据明确为未提供。未知诊断仍须可见，不用JSON转储兜底。

sync和recheck分别反馈安排/合并或已在处理，不宣称采集或入账完成；recheck明确通过后继续入账、未通过保持暂停，不能显示自动重试时间。交互处理结果保留意图保存但待核实的区别，不能把决定保存显示为账本写入成功。help用中文说明用途、最少参数和副作用。

使用Text或禁用markup展示外部内容；控制台业务详情不进入运行日志。真实Rich渲染与PTY回归覆盖大量同类问题、空列表、长ID/中文内容、窄终端、日志交错和退出行为。

## 9. 交互式问题处理契约

### 范围与接口

适用于统一run的issues导航。公开命令保留issues（可带原有对象筛选）与recheck，删除console及CLI resolve及其补全/帮助，不保留别名。application.resolve仍是原人工处理用例，不能因删除命令而删除版本校验、事务或UNKNOWN边界。

内部接口（不作为CLI参数暴露）：`issue_detail(store, selected)`返回当前问题、可执行动作、冻结决定及未决状态；`issue_candidates(store, ledger, selected, target_id=None)`返回实时候选、账户和分类；`resolve(..., expected_issue=None)`可带交互快照进行锁内校验；`request_recheck(store, targets=None)`的targets为已展示问题快照列表，None保留原全部重复问题复查语义。

### 输入输出与状态

交互在同一个PromptSession上按分组→对象→操作导航；箭头选择、Enter确认、Esc返回，Ctrl+C/EOF停止console和自有worker。菜单携带已展示对象、诊断与决定版本，用户不填写这些字段；关联其他账单时可显式输入远端ID。普通重查自动填操作来源，忽略、来源接纳、确认新建等人工判断要求理由。

单笔/组内recheck传递已展示的对象快照范围，只安排一次，复用冻结分类且不递增版本；不将分组操作扩大为全库。已接受命令线程必须完成后再退出，不能取消线程后显示未执行。查看候选只读账本并展示时间、金额及币种、账户、分类和商户备注，远端I/O不持行锁。

### 错误矩阵

- 版本/状态/问题变化：明确提示并刷新，要求重新选择；不以新版本自动重放旧操作。
- 候选查询失败：显示失败，不等同记录不存在，不据此确认新建。
- UNKNOWN/DISPATCHING：等待核实或记录意图，不重新发送、不显示入账成功。
- 邮件多诊断：忽略和重解析影响整封邮件，确认时说明。
- 对账差异等无处理动作：仍展示问题及下一步，不制造通用解决按钮。
- 业务字段包含终端控制字符或markup：以安全文本展示，不执行或解释。

### 正常、基础与错误案例

正常：重复候选组选择全部重新查重，显示安排/等待/跳过，再刷新查看worker进度。基础：Esc退出选择不写库。错误：旧选项已过期后静默换版本提交，或将普通retry混作冻结决定的recheck。

### 必需测试

原动作覆盖、旧resolve命令拒绝、取消零写入、邮件整体影响、单笔及组内快照范围、版本冲突无重放、候选缺失/失败、账户修正、UNKNOWN不重发；真实按键覆盖长列表滚动、中文与日志交错、理由输入及子菜单Ctrl+C/EOF与worker收尾。后端测试整体60秒硬超时，均用合成数据。

### 错误与正确

错误：在界面重写一套处理SQL或绕过resolve校验；每页启动独立stdin读取任务。正确：复用应用用例及动作规则，一个输入会话切换导航，持续观察worker和日志故障。
