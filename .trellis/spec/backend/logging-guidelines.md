# 日志与原件

后台经 `adapters/logging.py` 输出同一 JSONL 事件到终端和 `worker.jsonl`。由唯一 worker 持有文件及轮转；CLI 不与后台争写日志文件。

字段包含 UTC 时间、级别、固定事件名称，以及白名单内的 `job_id/source_row_id/attempt_id/target_id/error_type/duration_ms`。调用点使用固定事件名称，不能将原件、HTTP 响应、连接串或任意异常字符串拼进事件名称。

原件、业务审计、运行日志各有职责：原件保存不可变邮件；数据库保存业务事实与操作状态；日志服务于诊断。日志轮转不得清理原件或数据库记录。

默认日志容量为 10 MiB、归档数量为 5；配置可改变容量，不承诺固定保留天数。Docker 使用 `local` 驱动限制终端日志容量，应用日志另行宿主机挂载。

创建目录失败或运行中文件写入失败必须显式失败，不转写临时目录。`StrictFileHandler.handleError` 向 stderr 输出安全诊断并抛出错误。

验证：`tests/unit/test_logging.py` 覆盖文件/终端一致、重复初始化追加、轮转边界、非白名单秘密排除、磁盘故障与非法目录。本轮亦实际运行两个删除后重建的临时容器复用挂载，确认首条记录保留并追加第二条；这是容器挂载证据，不替代数据库备份恢复验证。
